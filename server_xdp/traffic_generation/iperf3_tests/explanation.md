# iperf3 UDP Traffic Generation and Test Findings

## 1. iperf3 Command

The UDP traffic was generated using the following `iperf3` command:

```bash
iperf3 -c 192.168.50.1 -u -b 500M -l 1472 -t 30
```
### At receiver:
                iperf3 -s


### Command Options

| Option | Description |
|---|---|
| `-u` | Use UDP |
| `-b 500M` | Offered traffic rate of 500 Mbps |
| `-l 1472` | UDP payload size of 1472 bytes |
| `-t 30` | Run the test for 30 seconds |

### Important Distinction

The `-b` option specifies the **offered traffic rate** that `iperf3` attempts to generate. It does **not** guarantee that the sender will actually transmit traffic at that rate.

The actual achieved bitrate and PPS depend on factors such as:

- NIC bandwidth
- CPU processing capability
- Packet size
- Packet rate (PPS)
- System and network limitations

---

## 2. Bitrate and PPS Relationship

For a fixed UDP payload size, the approximate relationship between payload size, PPS, and bitrate is:

```text
Bitrate (Mbps) = (Payload Size × 8 × PPS) / 10^6
```

Where:

- **Payload Size** = UDP payload size in bytes
- **PPS** = Packets Per Second
- **Bitrate** = Generated traffic rate in Mbps

For example, with a payload size of `1400 bytes` and `90,000 PPS`:

```text
Bitrate = (1400 × 8 × 90,000) / 10^6
        = 1008 Mbps
```

# 3. Test Setups

## Setup 1 — Laptop A to Server

- **Sender:** Laptop A
- **Receiver:** Server
- Traffic was generated by `iperf3` running on Laptop A.
- Laptop A has a **1 Gbit/s NIC**.

## Setup 2 — NVIDIA Jetson AGX Orin to Server

- **Sender:** NVIDIA Jetson AGX Orin
- **Receiver:** Server
- Traffic was generated by `iperf3` running on the Jetson AGX Orin.

# 4. Findings

## 4.1 Setup 1 — Laptop A, 1400-Byte Payload

In this test, the UDP payload size was kept constant at **1400 bytes** while the target bitrate and PPS were gradually increased.

At:

```text
Target PPS     = 90,000
Target Bitrate = 1008 Mbit/s
Payload Size   = 1400 bytes
```

the achieved values were approximately:

```text
Achieved PPS     = 85,000
Achieved Bitrate = 995 Mbit/s
```

The achieved bitrate approaches the **1 Gbit/s NIC limit of Laptop A**.

Increasing the target PPS and bitrate beyond this point did not result in a significant increase in the actual achieved traffic.

This indicates that the **sender NIC becomes the limiting factor**.

The behavior can be observed in the corresponding Excel table.

## 4.2 Setup 1 — Laptop A, 40-Byte Payload

In this test, the UDP payload size was kept constant at **40 bytes**, while the target bitrate and PPS were gradually increased.

At:

```text
Target PPS     = 250,000
Target Bitrate = 80 Mbit/s
Payload Size   = 40 bytes
```

the achieved values were approximately:

```text
Achieved PPS     = 197,303
Achieved Bitrate = 65 Mbit/s
```

Increasing the target PPS and bitrate beyond these values did not produce a significant improvement in the achieved traffic.

With a small **40-byte payload**, a much higher PPS is required to achieve a given bitrate. Therefore, packet-processing overhead becomes more significant and limits the achievable PPS.

## 4.3 Setup 2 — NVIDIA Jetson AGX Orin, 1400-Byte Payload

In this test, the UDP payload size was kept constant at **1400 bytes** while the target bitrate and PPS were gradually increased.

The NVIDIA Jetson AGX Orin achieved approximately:

```text
Maximum Bitrate = 1.35 Gbit/s
Maximum PPS     = 121,935
Payload Size    = 1400 bytes
```

Unlike Laptop A, the Jetson was able to exceed the **1 Gbit/s** throughput achieved by the laptop.
but still it was  significantly less than its hardware capabaility .

# 5. Test Conditions and Measurement Method

The following conditions applied to these tests:

- Cards specs : Laptop: 1Gbit/s , server : 10Gbit/s , Jetson: 10Gbit/s 
-No multiple `iperf3` streams were used.
- CPU affinity (`taskset`) was **not** manually configured.
- Traffic generation parameters were configured using `iperf3` from the terminal in **userspace**.
- Sender-side bitrate and PPS values were obtained from the `iperf3` output.
- Receiver-side traffic measurements were collected from the **NIC RX statistics**.
- The tests were performed using different fixed UDP payload sizes, primarily **1400 bytes** and **40 bytes**.

---

# 6. Overall Conclusion

The tests show that the **offered bitrate configured with `iperf3` is not necessarily the same as the achieved bitrate**.

The maximum achievable traffic depends on both **packet size and packet rate**:

- With a **1400-byte payload**, Laptop A reached approximately **995 Mbit/s**, which is close to its **1 Gbit/s NIC limit**.
- Increasing the offered bitrate beyond this point did not significantly increase the achieved throughput.
- With a **40-byte payload**, Laptop A reached approximately **197,303 PPS** and **65 Mbit/s**.
- The NVIDIA Jetson AGX Orin achieved approximately **1.35 Gbit/s** and **121,935 PPS** with a **1400-byte payload**.
- Therefore, **NIC bandwidth alone does not determine the maximum achievable UDP traffic**. Packet size, PPS, CPU processing, and the capabilities of the sender's networking stack and NIC also play important roles.
